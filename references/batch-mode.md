# Batch mode

Used when the user pastes several vacancies (texts, or links that open).

## Steps

1. For each vacancy, run the quick pass: blockers first (`fit-rubric.md`, section 1), then Musts vs CV.
2. Don't ask per-vacancy questions in batch mode. Collect them and ask once at the end, only the ones that can change a decision.
3. Don't build the full output for every vacancy. Full analysis only for the ones that pass.

## Output

**Summary table** – one row per vacancy:

| # | Vacancy | Verdict | Main reason | One thing to check |
|---|---|---|---|---|

Verdicts are the same four as in single mode, each starting with its mark: ✅ apply · ⚠️ apply with questions · ❓ needs a check first · ❌ skip. No numbers.

**Patterns** – 3–5 lines:
- What the good ones have in common.
- Which gap blocks the most vacancies (so the user knows what is worth learning or proving).
- Which CV fix would help across several of them.

**Questions that decide this** – at most 3, collected from all vacancies, each multiple-choice (`intake.md`) and tied to the verdict it can change.

**Next** – which vacancies deserve the full analysis, in the order the user should do them.

## Notes

- If two postings are the same job (same company, same text), say so once and treat them as one.
- If a link can't be opened, mark the row "text needed". Don't guess.
- Salary numbers that a job board estimates are not from the company. Say which is which.
